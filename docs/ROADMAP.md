# Roadmap

Phases are sized to end in something visibly working. Each has acceptance criteria — a phase isn't done until they pass on `docker compose up`.

## Phase 0 — Research & architecture ✅ (2026-09-03)
Deep research (docs/research/), architecture (ARCHITECTURE.md), decision log, repo bootstrap (compose blueprint, env template, gitignore).

## Phase 1 — Skeleton that runs ✅ (2026-09-03)
Scaffold `client/` (Vite + React + TS + R3F) and `server/` (ASP.NET Core 10 minimal API + EF Core + Npgsql), Dockerfiles with `dev` targets, wire compose + compose watch, Vite proxy `/api` → server.
**Accept (all verified):** `docker compose up --build --watch` → spinning red wireframe cube at :5173, `GET /api/health` returns `{ status: "breached", db: true }` through the proxy, EF `InitialCreate` migration applies to Postgres on boot, hot reload verified on both sides (client HMR without reload; server restart ≈5s).

## Phase 2 — The Blackwall journey ✅ (2026-09-03)
Scroll rig (Lenis + ScrollTrigger → zustand progress), Act 1 Blackwall, Act 2 contact spike (Glitch/CA ramp), Act 3 instanced data tunnel, Act 4 dissolve into a placeholder room shell, postFX chain with per-act presets, boot/loading screen.

**Wall redesign (2026-09-03, same day, at Edi's direction — supersedes the original noise-plane wall).** The Blackwall is no longer a domain-warped FBM plane; it is a *holographic laser lattice* (see D-09). Roughly 5.2k instanced dashed beams fill a 46-unit-deep volume the camera walks **between**, all feeding a white-hot horizon line at eye height that grows on approach until it whites out the frame. Frame cost measured 4.07 ms high / 2.77 medium / 2.46 low at 1265×720 — cheaper than the plane it replaced, because a beam is four triangles and a dash is a `fract`, where the plane paid 11 simplex evaluations per fragment across the full screen.
**Accept (all verified):** full 0→1 scroll plays all five acts as one continuous dive; frame cost flat at 9.6–10.1 ms across every act (1265×800, dpr 1, AMD Renoir iGPU — see the caveat below); quality tiers switch live via `PerformanceMonitor` with no crash or artefact; reduced-motion path drops Lenis, shake, Glitch, grain, the strobe and half the scroll length; zero React re-renders driven by a scroll frame (measured — 400 progress writes → 8 renders, all from mode flips); compiled program count constant at 12 through repeated up-and-down sweeps, so nothing recompiles mid-dive; `npm run typecheck` and `npm run build` green; verified identically through `docker compose up --build --watch`.

**dpr caveat.** The dev machine is an AMD Renoir *integrated* GPU on a dpr-1 display, i.e. below the "mid GPU" bar and unable to exercise dpr 2 at all. The full chain measures 12.0 ms high / 11.9 medium / 10.6 low at dpr 1, so the ~60 fps target holds here with headroom, and a mid-range discrete GPU has 3–5× the fill rate needed for dpr 2. Confirming 60 fps at dpr 2 needs a hi-dpi machine, and `PerformanceMonitor` covers the case where it does not hold.

## Phase 4 — WALLET.SYS ✅ (2026-09-04) — plan: [docs/plans/phase-4-wallet.md](plans/phase-4-wallet.md)
Wallet + budgets backend (entities, invariants, endpoints per ARCHITECTURE §5–6), seeding on first login (dev: seeded local user until Phase 5 auth lands), terminal commands wired to typed API client, themed errors (overdraft, cooldown), history table rendering.

**Brainstorm outcomes (2026-09-04, with Edi — see D-11…D-14):** salary is claimable once per *calendar* window in the user's timezone (monthly default), with a one-shot `salary --force` escape hatch per window (2 claims max); budget `Reached` is **celebration only** — auto-locked by the crossing fund call, escrow stays, the user buys the item in real life and cancels to reclaim (no purchase mechanic, `budget done` dropped); a **config command family** lands this phase (`config list/get`, `sudo config set/reset` over a server-side validated registry: `wallet.salary.cadence`, `wallet.salary.amount`, `wallet.account.alias`, `wallet.history.pagesize`) — mutations without `sudo` get a themed `PERMISSION DENIED`; extras in scope: `stats` command, `history` filters, ASCII budget progress bars, consistent `€$` formatting. GitHub connection (Phase 5) will use the OAuth *device flow* from the terminal (D-14).

**Accept (all verified 2026-09-04):** pay/income/salary/history/stats/budget/config lifecycle all work end-to-end — every command exercised through the real den terminal in the browser (themed output, aligned tables, `€$` formatting, progress bars) and the full API surface torture-tested via curl; data survives `docker compose restart server db` (seeder idempotent, skips a non-empty db); overdraft, double-salary-claim, and double-force refused **server-side** with typed codes the terminal themes (`--force` hint on the second claim, verified in-terminal); salary windows are calendar-bucketed in the user tz via `X-Timezone` (monthly `2026-09` / weekly `2026-W36` both exercised; cadence flips live via `sudo config set wallet.salary.cadence weekly` — a *unit* test for the window-key function is still owed when a test project lands); budget fund clamps overfund + auto-Reaches in the crossing call (celebration block), cancel refunds from Reached, `rm` refuses once transactions exist (FK-backed) and deletes when clean; config registry validates unknown key / bad value / missing sudo, each themed distinctly; money conservation held exactly (`Balance == Σ signed transactions`, checked in psql after ~20 mutations incl. clamps, refunds and forced payroll); typecheck + build green; ESC exit and den re-entry unaffected.

*Verification caveat:* the in-app browser pane freezes rAF while hidden, so the den dolly was frame-pumped with synthetic pointer events and WebGL screenshots come back black — terminal verification is via DOM text capture (stronger evidence anyway). The dev DB was reset to a fresh seed before the terminal pass; current state reflects that pass (September salary drawn once, `--force` still available, Sandevistan at €$ 300).

## Phase 5 — REPO.NET + auth ✅ (2026-09-04) — plan: [docs/plans/phase-5-reponet.md](plans/phase-5-reponet.md)
GitHub is the login (D-06), connected via the OAuth **device flow** from inside the CRT (D-14): `login` prints `ENTER CODE XXXX-XXXX AT github.com/login/device`, the server polls GitHub and vaults the token (Data-Protection encrypted on the user row, key ring in Postgres — D-15), the session is a 30-day sliding cookie. First login **claims the unlinked dev seed** so the Phase 4 ledger survives; later identities get a fresh account with one €$ 2,077.00 welcome row. Every wallet/budget/config/repo route went behind the cookie. REPO.NET reads GitHub through a typed `HttpClient` (not Octokit — research 03 §4) with a 60s per-user cache, `If-None-Match` revalidation and `X-Cache` verdicts; commands `repos / repo / latest / commits / prs [--all] / rate`, plus `login/logout/config` shared with WALLET.SYS and a `repo.default` config key. No auth backdoor: offline dev runs the real code path against `tools/github-stub` (fake github.com + api.github.com with a device-approve page, ETags, Link paging, rate headers) behind `compose.github-stub.yml`.

**Accept (all verified 2026-09-04, through compose + the stub overlay):** fresh browser → `balance`/`repos` in either skin → `ACCESS DENIED — run: login` (motd shows the same hint after the banner); `login` runs the whole ceremony inside the CRT in *both* terminals — code printed, popup fallback line when `window.open` is blocked, approval at the stub's device page → `UPLINK ESTABLISHED // operator :: v-netrunner`; the first identity claimed the seeded Phase 4 ledger (13 transactions, €$ 6,481.76, conservation exact: balance == Σ signed amounts in psql) and a second identity got its own account with the single welcome row while the first was untouched; every REPO.NET command rendered through the terminal with a cache-verdict line — `X-Cache` observed MISS → HIT (repeat within 60s) → REVALIDATED (after expiry; server log shows `:: REVALIDATED 304 // rate 4983/5000`, i.e. rate-free), `rate` is BYPASS, unknown repo → themed `REPO_NOT_FOUND`; `repo.default` round-trip (unset → `NO TARGET` hint, `sudo config set` → bare `latest` resolves, reset restores); `logout` → `UPLINK SEVERED`, next command denied, `/api/me` 401; session cookie **and** vaulted token survived the containers being destroyed and recreated mid-sweep (stronger than the planned `restart server` — Data Protection key ring persisted in Postgres); client typecheck + build and server build green (0 warnings).

*Verification caveats:* the dev machine has no GitHub OAuth app, so the ceremony ran against the stub (the point of D-15.3 — same code path, fake far end); the real-GitHub leg needs an OAuth app with **Enable Device Flow** ticked and is the only thing not exercised. The in-app browser pane coerces `window.open(…, '_blank')` into same-tab navigation, so the popup-blocked fallback path is the one the CRT pass exercised (correct behavior — the code treats the open as best-effort). As in Phase 4, the pane freezes rAF while hidden: the den dolly was driven with the debug `__seek` + synthetic `__advance` frames and verified by DOM capture.

### Suggested order of risk
The novel/artistic risk is front-loaded on purpose: Phase 2 (shader journey) is the make-or-break piece; Phases 4–5 are conventional CRUD/API work we can't really fail at. If Phase 2 needs more iterations, steal time from Phase 6.

*Phase 2 postscript (2026-09-03): it landed without eating Phase 6's budget. Deviations from the plan, all deliberate and measured — tunnel streak counts are 900/550/320 rather than 2500/1200/600 (at the planned density the band renders as a solid sheet of light, whatever the radius or thickness); the camera curves are sampled with `getPoint`, not `getPointAt`, because the plan's control points were spaced for uniform parameterization and arc length dragged the pierce from t≈0.37 to t≈0.31; and the postFX chain needs three `EffectPass`es rather than one, since postprocessing refuses to merge a UV-warping effect with a convolution effect and `ChromaticAberration` is itself flagged CONVOLUTION. Phase 3 debt: none from the dissolve — `onBeforeCompile` worked, so the wireframe-crossfade fallback was not needed.*
